## 4. 完整下载门槛

“已下载”与“完全下载”分开。只有完全下载的数据集才进入“已下载资产” TSV；部分下载、下载中和仅有样例的项目不计入，除非用户明确要求列出候选。

完整下载至少需要：

- 预期文件/分片清单与实际文件一致，或固定 revision 的 tree/manifest 已逐项核对；
- 文件非零，expected bytes、实际大小或 hash 能核对；
- 归档可执行 CRC/格式检查，Parquet/JSON/XML 等至少能做结构读取；
- 没有未完成的 payload。`.incomplete`、`.partial`、`.crdownload`、下载锁和临时缓存不算数据文件；
- 预计的分卷文件必须按 manifest 判断。比如 `part-000` 到 `part-009` 是官方完整分片时，不因为文件名含 `part` 就判定为部分下载；
- ModelScope/Hugging Face 的“completed”状态只能作为证据之一，不能替代本地文件清单和大小核对；
- `.cache`、`.tmp`、`.filter_tmp`、`._____temp`、系统隐藏目录和下载工具 metadata 不计入 H 数量。若临时目录只有空骨架，在 P 中说明即可。

完整归档可以保留 tar/zip，不要求为了验证而全量解压；需要抽样时使用成员枚举、流式读取或定向解压。

## 6. 输入、标签与可用性

### 输入与标签

- 有真实 ground truth、参考 Markdown、结构化版面/表格/公式标签或问答答案时，写成 `输入 -> 标签`。
- 没有标签时只写输入，不写箭头；不要写 `输入 -> 无标签`、`输入 -> 无人工标签`，也不要把标题、来源、页数、文件名和普通 metadata 当标签。
- 标签可以是弱标、teacher 生成或程序生成，但必须在 P/L 说明来源和质量边界。
- `supportData` 没有人工作答/结构标签时，M 只能写“客服附件原始文件（文档/脚本/配置/图片/压缩包）”，不能补造标签。

### 可用性判定

按以下优先级判断：

1. `非数据集`：索引、目录、工具、搜索页或纯来源说明，不是独立数据资产。
2. `暂时不可用`：下载失败、权限阻断、加密无法读取、文件损坏或无法确认 payload。
3. `仅评测`：明确为 benchmark/evaluation，标签用于测评，不作为训练数据主料。
4. `可用`：能直接作为 `pdf-markdown` 输入/目标对使用，同时具备可读 PDF、对应参考输出/ground truth 和稳定配对。
5. `缺label`：有输入但没有目标任务对应的标签/参考输出；格式可读、已解压或已下载都不能改变这一结论。
6. `需处理`：已经确认存在标签或参考输出，但还需解包、格式转换、结构化解析、join 或重新配对。

补充：

- “PDF 能打开”只证明输入文件可读，不证明有标签。
- 只有 PDF 的法律、登记、处罚、标准文书填 `缺label`，不能因为能被解析器读取就填 `可用`。
- FinanceBench 的 `question/answer/evidence` 是问答标签，不是 `pdf-markdown` 参考输出，所以填 `需处理`，M 保留 `财务报告/问答 JSONL -> 问题、答案、证据文本、财务指标/来源页`。
- 公式裁剪、场景 OCR、表格图像等非 PDF-Markdown 资产，若已有标签通常填 `需处理`；明确评测集填 `仅评测`。
- 旧 XLSX/旧 TSV 中已有的 M/N 值不自动批量改写；只有用户明确要求重新判定时才回溯。新增行必须遵守本节规则。
