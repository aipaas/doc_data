## 一、指标口径

305 是资产名录，不是 305 个等价样本。以下指标把任务价值和获取状态分开：

| 指标 | 明确定义 | 用途 |
| --- | --- | --- |
| 名录覆盖 | 状态为团队硬盘、百度网盘、柯博电脑、迅雷云盘或文启 VTT | 只说明“登记为已取得”，不代表当前可挂载或可训练 |
| 标题核心池 | 物理多页=`✅`，关联=`高/中`，且不是`非数据集` | 当前标题修复采集的主分母 |
| 标题价值权重 | 高=2，中=1；低、不相关、非数据集=0 | 防止低价值条目和核心监督数据等权 |
| 通用 OCR 池 | 类型包含`OCR`、`文档图片`或`版面`，且不是`非数据集` | 单独评估通用 OCR，不与标题任务混算 |
| 标签就绪度 | 分开统计`可用/需处理/仅评测/缺label`和是否存在真实箭头配对 | 防止“文件已下载”被误写成“训练数据已完成” |

已知别名 `DocHieNet/HierDoc` 在高价值家族统计中只计一次。其他未确认同源的条目不强行合并，因此加权分数是透明的规划指标，不是模型质量分数。

## 四、现在是否继续下载

### 默认结论：暂停一般性下载

当前可用空间约为：`shareData1 206 GiB`、`shareData5 200 GiB`、`shareData3 64 GiB`、`shareData2 20 GiB`。保留 20 GiB 余量后，放不下任何剩余的大型高价值候选。

### 满足条件才下载

| 候选 | 启动条件 | 优先级 |
| --- | --- | --- |
| HRDoc | 获得可访问的官方镜像或 Drive 转存 | 最高：直接标题层级监督 |
| `pixparse/idl-wds` | 单盘至少约 2.39 TiB 可用 | 高：多页 OCR 行框和阅读顺序 |
| ESGDoc / FinDocBench / CompHRDoc | 官方 payload 或 HRDoc-Hard 依赖恢复 | 高，但当前不能形成完整样本 |
| 国务院/地方政府公报 | 先固定年份、栏目、期次和截止快照 | 中：只完整下载定义后的批次 |

### 当前不应下载

- `PubMed-OCR`：320.45 GiB，当前盘放不下，且没有标题金标。
- `Docmatix`：914.41 GiB，标签以文档问答为主，标题收益低。
- PMC OA 全库：约 10.59-26.18 TiB；应定义可复现 PDF+JATS 子集，不能下载全库。
- 国家电子教材：约 207.914 GiB，附件接口 403，保留余量后也放不下。
- DocGenome、UniRec40M、BigDocs、PIN、OBELISC 等复合或外围大库：标题监督收益不足。
- 发改委名称清单、最高法 HTML 库、GGZY、CCGP 等索引或无固定边界门户：先修资产身份和采集边界。

## 五、下一阶段的数据采集工作

### P0：把已取得资产变成标题任务

统一最小 schema：

```text
document_id, page_no, block_id, bbox
raw_ocr_text, corrected_title_text
role, level, parent_id, reading_order, cross_page_link
label_source, confidence, correction_type
```

处理顺序：

1. 对账 `pixparse/pdfa-eng-wds` 和 READoc 的真实盘位；核实其他 session 的 3 条“下载中”。
2. 转换 `DocHieNet/HierDoc`、READoc、`pixparse/pdfa-eng-wds`，先产出可训练/可评测的统一记录。
3. 从合同库 API 记录标题、DOC/DOCX 样式、PDF 原生文本、章节编号和条款编号生成弱标，并保留 `label_source/confidence`。
4. 优先处理职业教育标准、义务教育课程标准和合同库；低页数模板只作补充分布，不按数据集数量等权。

### P1：构造真正的“错误输入 -> 正确标题”

必须覆盖：OCR 漏字/错字、标点和空格、编号体系错误、标题与正文误合并、标题拆块、页眉误判、跨页标题、重复标题、层级和父子关系错误。弱标、模型生成和人工 gold 必须分层保存。

### P2：建立中文多页 gold 集

- 第一阶段 200-300 个文档，覆盖政府公报、标准、招投标、财务、教材和科技论文。
- 同时覆盖 born-digital PDF 与扫描 PDF，并按页数分层。
- 文档级、来源级和模板级切分；相同模板不得跨 train/dev/test。
- dev/test 双人复核，保留争议、修改原因和原始 OCR。

下一阶段的主 KPI 不再是 GiB 或数据集行数，而是：可追溯标题配对数、人工 gold 文档数、真实 OCR 错误类型覆盖、长文档/跨页覆盖和模板泄漏率。

## 六、未下载复核与执行边界

2026-07-30 对账按用户口径忽略 I 预览和 P review 备注：完整下载 TSV 的 8 行与新版 XLSX 的实质字段已经一致，继续保留为完整落盘证据台账，不再视为待回填清单；未下载修正 TSV 已从 12 行缩减为 3 行，只保留 HRDoc、电子教材和最高法样式库仍需清理的 L 备注。状态枚举已统一使用新版 XLSX 的`无法下载or部分下载`，整行粘贴不会回退新版字段。

| 阻断类型 | 代表数据 | 处理 |
| --- | --- | --- |
| 只有容量不足 | `idl-wds`、PubMed-OCR、Docmatix | 保持“确认可用还未下载”，不能降为暂时不可用 |
| 权限或入口阻断 | HRDoc、DocILE、台湾立法院、电子教材 | 记录实际探针和恢复条件 |
| 非数据集/索引 | 发改委名称清单等 | 修正类型、多页和可用性，不下载 |
| 持续更新、无固定边界 | PMC OA、公报、门户 | 先定义 revision/时间范围，再谈完整下载 |

只有同时满足以下条件才进入完整下载 TSV：官方来源和完整边界明确；单盘可容纳 payload、验证临时空间和至少 20 GiB 余量；无缺失或 part；清单、大小和可读性通过；输入与真实标签 schema 已核验。否则只记录字段复核或阻断，不把样本、metadata 或部分 payload 写成完整资产。
