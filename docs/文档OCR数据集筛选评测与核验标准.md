# 文档 OCR 数据集筛选、评测与核验标准

状态：2026-07-31。本文是面向项目维护者的字段规范；两个可分发 skill 自包含全部运行规则，不以本文或其他项目文档为前置依赖。用户当前指令始终优先。

## 1. 目标

每条数据集记录必须明确回答：

1. 数据集是什么，是否为独立数据资产；
2. 具体输入是什么，是否存在配对标签或参考输出；
3. 是否包含真实的物理多页文档；
4. 对“多页文档 OCR 标题修正”的关联程度；
5. 结论来自复用、公开元数据、代表样本还是完整资产；
6. 还存在哪些访问、格式、许可或人工 Review 限制。

不能用数据集名称、平台任务标签或文件扩展名单独代替核验。

## 2. 证据与验证状态

### 2.1 操作顺序

按以下顺序处理，避免重复下载和重复验证：

1. 复用原资产表、已接受的 checkpoint、既有验证记录；
2. 检查已下载的外置盘文件、manifest、日志和元数据；
3. 查看官方 Dataset Card、README、论文、schema、固定 revision 文件树；
4. 仍无法判断时，优先通过镜像下载少量代表样本；
5. 只有完整性任务明确需要时才下载完整数据集。

复合数据集、合集、搜索入口和索引不拆分验证；保留原行，写明其实际是合集、入口、索引或工具。

### 2.2 证据强度

| 层级 | 可确认内容 | 不能声称 |
| --- | --- | --- |
| 完整资产核验 | 文件清单、大小、结构、代表内容及本地可读性 | 未执行的全量人工质量 Review |
| 样本核验 | 样本输入、标签字段、页数、配对关系和可解析性 | 整个数据集均完整或质量一致 |
| 官方 schema/tree 核验 | 字段、格式、分片、目录和官方任务定义 | 原始 payload 已打开或本地可用 |
| 官方 README/Dataset Card 核验 | 官方描述、规模、许可和预期任务 | 样本内容、真实页数或标注质量已验证 |
| 原表/历史结果复用 | 已有结论和来源链 | 本轮重新下载或重新核验 |
| 名称/聚合索引 | 仅作候选线索 | 输入、标签、多页或可用性结论 |

“已核验-公开 README/schema”是元数据核验，不等于样本核验。验证状态必须写明证据边界，禁止笼统写“已验证”。

### 2.3 验证备注

验证备注至少包含：

- 证据来源和固定 revision/版本；
- 实际查看的是 README、schema、文件树、Range 样本、本地样本还是完整资产；
- 检查到的输入、标签、页数或目录组织；
- 未检查的部分和当前限制；
- 是否复用已有结论、是否避免重复下载。

### 2.4 未下载情况下的字段复核

“未下载”是获取状态，不是“所有字段都无法判断”。固定 revision、官方文件树、schema、README、API 清单和受控访问探针可以支持字段修正，但证据备注必须明确写 `未下载`，且不得把公开元数据表述为本地样本或完整资产核验。

| 证据 | 可以修正 | 不得声称 |
| --- | --- | --- |
| 官方身份页、仓库、许可 | 数据集身份、来源、官方链接、访问条件 | payload 可读、标签或多页 |
| 官方 README/Dataset Card | 官方描述的输入、任务、规模、划分 | 已实际打开样本、全库质量一致 |
| 官方 schema/代表记录 | 数据类型、具体输入、真实标签、是否需转换 | 全库完整、本地可用 |
| 固定文件树/manifest | 文件数、远端总字节、版本边界、是否大于 500GB | 已下载、已有存储路径 |
| 明确页序字段或物理多页格式 | 是否多页 | 未查看 payload 时的页数分布 |
| 镜像/官方受控探针 | 可访问、需 token、403、死链、损坏或传输阻断 | 未完整传输文件的完成状态 |

下载状态 D 与任务可用性 N 分开判断：

- 公开数据只有容量不足：D 保持`确认可用还未下载`，N 按真实标签判定；容量不足不等于`暂时不可用`。
- token、密码、持续 403、死链、损坏或镜像与官方通道均阻断必要 payload：D=`无法下载或部分下载`，N 才可判`暂时不可用`。
- schema 已证明具体输入但不存在配对标签：M 只写输入，N=`缺label`；无需为了写“缺label”而完整下载。
- schema 已证明有配对标签但需要 join、转换、重组或任务适配：M=`输入 -> 标签`，N=`需处理`，仍遵守`仅评测 > 缺label > 需处理`。
- 索引、名称清单、搜索入口、工具/模型仓库或零散示例：N=`非数据集`，不能用下载失败掩盖其真实性质。

未下载修正单独写入 16 字段 TSV，一数据集一行；E/K 不填虚假的本地盘与路径，P 写清 revision/发布边界、证据层级、探针结果、阻断原因、可支持的修改和不能支持的结论。未下载行不得混入完整下载 TSV。

## 3. 资产表与存储

项目默认资产表为 16 字段，不包含 O 列：

```text
行号
A 数据集
B 来源
C 类型
D 状态
E 团队硬盘
F 是否多页
G 是否>500GB
H 数量
I 预览
J 原始链接
K 存储链接
L 备注
M 输入与标签
N 可用性
P review备注
```

- 一个数据集一行，稳定名称和行键必须与当前源表一致；自定义 schema 按字段语义映射，不硬套列字母。
- B 来源和 C 类型为多选，使用英文逗号分隔；D 状态和 N 可用性为单选。
- E 写团队逻辑盘名，不把它当作固定挂载路径；K 写本轮实际存在并核验过的数据集目录。
- 盘未挂载时只记录“当前不可访问”，不能仅凭这一点改写 N 或判断资产已删除。
- H 写文件数、记录数、页数和实际占用，大小统一使用 `MiB` 或 `GiB`，排除缓存、锁和临时文件。
- J 始终写官方项目页或下载页。镜像只记录为传输通道，不能替代资产来源。
- P 记录 revision、证据层级、清单/大小/结构结果、抽样边界和未检查部分；自动检查不能冒充人工 Review。

B 来源使用项目当前受控枚举；没有项目枚举时记录规范平台名和官方来源。C 类型默认只能取：

`表格图片`, `文档图片`, `图表`, `OCR`, `文档文件`, `网页`, `公式`, `通用图文`, `版面`

原资产表 C 已有合法值时直接复用；缺失时按 payload/schema 推断，可多选但不能重复或扩展新枚举。

## 4. 输入与标签

只使用一个“输入与标签”字段。

- 有真实配对标签：写成 `具体输入 -> 具体标签`。
- 没有配对标签：只写具体输入，例如 `多页 PDF`、`文档页面图像`、`财经文本 JSONL`。
- 禁止在输入字段单独写 `缺label`。
- 禁止写 `输入 -> 缺label`、`输入 -> 无标签` 或 `输入 -> 无人工标签`。
- 无标签结论写入“可用性”，不是写进输入字段。
- QA 答案、类别、版面区域、OCR 文本、bbox、阅读顺序、Markdown、HTML、层级和 linking 只有在与输入配对时才算标签。
- 原字段为空不能直接推出缺标签；先查官方 schema 或代表样本。
- 复合/合集条目写明 `OCR 数据集合集`、`搜索入口`、`代码工具及示例`等实际输入形态，不编造统一标签。

## 5. 可用性

可用性只回答“当前资产能否直接用于目标任务，以及还需多少处理”。它与“是否多页”和“标题修正关联度”独立判定：有 label 只能说明不是 `缺label`，不自动等于 `可用`；标签需要抽取、重组或任务适配时仍为 `需处理`。

允许值：

| 可用性 | 判定条件 |
| --- | --- |
| `可用` | 必要资产可访问，输入与目标标签稳定配对，无需人工推断、跨源 join 或任务重构即可用于当前训练或评测目标 |
| `仅评测` | 官方定位或许可/划分只适合 benchmark、test 或评测使用 |
| `缺label` | 代表样本或可靠 schema 已可读，确认有具体输入但没有配对标签 |
| `需处理` | 有可用配对信息，但需要解包、确定性标签抽取、join、格式转换、页序重组、OCR 对齐或任务适配 |
| `暂时不可用` | 已实际尝试本地路径、优先镜像或官方源的小样本，仍因权限、密码、损坏、挂载、失效链接或传输阻断而无法取得必要资产 |
| `非数据集` | 搜索入口、资源索引、代码/模型仓库或只有零散示例，不构成独立数据集 |

“本地盘没有”“尚未完整下载”“只有描述”都不能直接推出 `暂时不可用`。公开条目必须先通过镜像或官方源取得 README、schema、Range 片段或代表样本；只有实际采样失败并记录通道与原因后，才能使用该状态。样本成功后必须继续判为 `仅评测`、`缺label`、`需处理`或 `可用`。

冲突时先判定“非数据集”；实际采样受阻时再判定“暂时不可用”。在 `仅评测`、`缺label`、`需处理`重叠时，严格使用：

`仅评测 > 缺label > 需处理`

因此，评测集即使没有公开标签仍保留“仅评测”；没有标签的数据不能只因为可转换而写成“需处理”。

## 6. 物理多页

只有满足下列至少一项才标 `✅`：

- 一个逻辑样本是实际多页 PDF、TIFF、DOCX、PPTX 或其他分页文档；
- 有明确的 `document_id + page_id/page_number`；
- 有可重建同一文档的有序页面列表；
- 有跨页 linking、目录、页序、续表或层级关系；
- 代表样本页数大于 1，且该样本与数据集发布粒度一致。

下列情况标 `❌`：

- 独立单页图片或单页 PDF；
- 多张彼此无关的图片；
- XML、HTML、JSONL、Parquet、网页或代码容器本身；
- 同一页面的多语言、增强、退化或不同截图版本；
- 只按文件夹收集页面但没有同文档归组证据；
- 仅凭名称含 `Doc`、`PDF`、`multi-image` 或文件很多。

PDF 也可能是单页，不能只按扩展名判多页。

## 7. OCR 标题修正关联与核心池

### 7.1 三个字段独立

- 关联度只评价“现有输入与标签对标题修正监督有多直接”；
- 是否多页只评价物理文档及页序证据；
- 可用性只评价访问状态、配对完整性和处理成本。

三者不得互相推导。有 label 不自动等于高关联；物理多页不自动等于中或高；单页标题强标注也可以高关联。

### 7.2 什么算标题直接监督

计入标题直接监督：文档主标题、章/节标题、Heading/Section-header 角色、标题文本、标题框与角色、标题层级/父子关系、Markdown `#` heading、HTML `h1-h6`、目录节点及其正文标题映射。

标题信号还必须与可对应 OCR 的输入载体配对，例如页面图像、PDF、可确定复现的页面渲染、逐页 OCR 输出或有序页图。只有标题清单、元数据或独立 XML/HTML 结构文本而没有页面/渲染映射时，不能判 `高`；若仍可通过渲染、join 或对齐生成监督，最多判 `中`。`高` 至少需要官方 schema 明确给出配对字段，或代表样本/完整资产实际证实配对；仅凭数据描述或名称最多判 `中`。

下列标签不能仅凭名称中的 `header` 或 `title` 计入：页眉/页脚、表头、表格标题、图注/图表标题、表单字段名、KIE 的 HEADER/QUESTION、QA 答案、普通 OCR 文本，以及没有 heading 语法或标题角色的泛化 Markdown/HTML。它们只有外围能力价值。

### 7.3 四档判定顺序

先执行身份门：索引、目录、工具/模型仓库、搜索入口、无统一 schema 的合集或零散 fixtures 若已判 `非数据集`，关联度必须为 `不相关`。

再按以下顺序判断：

1. 输入与标题专属目标是否配对，且可用确定性规则抽取标题文本、身份、层级或关系；
2. 若不能，是否仍有完整页面/文档上下文，以及 OCR、通用版面、阅读顺序、文档归组或真实多页原料，可用于生成标题候选或伪标签；
3. 若仍不能，是否只剩表格、公式、KIE、QA、场景/裁剪 OCR 或领域迁移价值；
4. 没有可信任务路径时判不相关。

| 关联 | 必要条件 | 典型例子 |
| --- | --- | --- |
| `高` | OCR 可对应的输入载体与目标配对，目标直接标出文档/章节标题的文本、角色、框、层级或关系；无需模型或人工先猜“哪一段是标题” | 图像 -> Title/Section 标签；PDF -> 含 heading 的 Markdown；有序页图 -> 标题树/目录映射 |
| `中` | 没有标题专属标签，但完整页面/文档上下文足以生成标题候选；或已有结构化标题但仍需渲染/join 才能对应 OCR 输入；标题身份、边界或正确文本仍需启发式、模型、人工或跨源对齐 | 多页 PDF 原料；页面图像 -> OCR+bbox+阅读顺序；独立 XML 标题结构 -> 待配对 PDF |
| `低` | 只有间接迁移价值，且缺少完整标题上下文或标题专属目标 | 表格/公式、KIE/表单字段、DocVQA、场景文字、裁剪文本行、普通单页 OCR |
| `不相关` | 不是独立数据集，或没有可信路径形成标题修正数据 | 搜索入口、名称目录、工具/模型仓库、无统一 schema 的合集 |

程序生成、teacher、弱标和官方结构标签可以构成直接监督；标注来源影响可用性、质量分层和后续质检，不自动把关联度降为中。混合任务数据只有在标题子集可按字段、任务名、提示词或标签确定性筛出时才能判高，否则最多判中。

关联原因必须写清四项：直接标题信号或其缺失、物理页序证据、所需转换、标签来源及质量边界。不能只写“有 Markdown”“可用于标题修正”或“没有跨页所以不是高”。

### 7.4 核心池口径

不得直接把全部资产行或全部高/中行称为核心池。按两级门槛统计：

| 集合 | 可复算定义 | 作用 |
| --- | --- | --- |
| 字段候选池 `C0` | `F=✅ AND P∈{高, 中} AND N!=非数据集` | 从表字段快速筛选，允许包含证据不足或边界未冻结的候选 |
| 证据合格核心池 `C1` | `C0`，且有官方 schema/代表样本/完整资产支持页序，数据集是独立固定 release 或已冻结快照/批次 | 作为采集覆盖率和缺口分母 |
| 多页监督池 | `C1 AND P=高` | 直接标题监督；再按 `可用/需处理/仅评测/暂时不可用`分层 |
| 多页原料池 | `C1 AND P=中` | 伪标签、弱标和人工 gold 的原始文档来源 |
| 单页标题支持池 | `F=□ AND P=高` | 训练标题检测/文本/层级子能力，不计入多页核心池 |

持续更新门户、搜索入口、只有名称的目录、未锁定子集边界的复合来源，即使可能包含多页文件，也只能进入“待冻结采集来源”，不能进入 `C1` 分母。下载受阻不改变任务价值；固定 release 已证实但暂时不可访问的条目仍可进入 `C1`，在可获取性统计中单列。

必须同时报告三种互不替代的量：资产行数、已知家族去重数、实际文档/页数。别名、镜像、明确子集或同一原始语料的派生版本在“原始来源覆盖”中去重，在“不同标签资产/处理工作量”中可分别保留。`高=2、中=1`只能作为 `C1` 内部的规划权重，不能冒充数据量、标注质量或模型收益。

## 8. 下载、完整性与临时验证

- 已有可追溯证据的资产不重复下载。
- 传输顺序默认 `ModelScope -> hf-mirror.com -> 官方 Hugging Face`；J 仍记录官方来源。
- GitHub 大文件优先使用已验证传输镜像，再回退官方端点；官方 URL 始终作为来源。
- 完整下载前固定 revision/版本和远端 manifest，并计算`完整 payload + 峰值验证临时空间 + 安全余量`；项目未指定时保留 20 GiB。
- 数据集必须完整放在同一磁盘。空间不足时不创建 partial，状态与可用性仍分开判断。
- 只需筛选时限制文件数和字节数，优先 Range、schema、Parquet 小片段或代表样本。
- 验证文件放在专用临时目录，不进入最终数据目录。
- 完整资产必须核对预期文件、非零状态和准确大小；不得残留未完成的 `.part`、`.partial`、`.incomplete` 或下载锁。
- 归档检查成员和代表成员；JSONL/Parquet/XML 检查 schema 和样本；PDF、图片和 Office 文件检查文件头、页数或代表内容。
- 远端摘要、本地完整摘要和首/中/尾抽样摘要必须分开记录。只做抽样时不得声称全文件 hash 或 CRC 通过。
- 样本、metadata 和部分 payload 不进入完整下载 TSV；未下载但有证据的字段修正写入独立 TSV。
- 记录结论后，只删除本轮创建的临时样本、chunk 和解压副本；不得触碰已有完整 payload、其他 session 的下载目录或可续传 partial。

## 9. 全量表与 Checkpoint

- 每个源记录只出现一次，名称与源表完全一致。
- checkpoint 小批量原子写入，不能等全部结束后才保存。
- 已验证结果优先复用，禁止重复下载。
- 难下载、复合、受限或非数据集行仍保留，并给出明确结论；不能留“待核验”。
- 关联原因必须数据集特定，不能重复整句。
- 验证状态必须可区分：复用、官方元数据、样本、完整资产、跳过下载。

交付范围始终由本轮用户指定的资产表或目标列表决定，不固化历史行数。不同来源的独立资产池只有在用户明确要求时才合并。

## 10. 交付前审计

至少检查：

- 单工作表、预期行数和列数；
- 所有源记录完整且无重复；
- 必填字段无空白，无 `待核验`、`未知`、`待确认`等占位符；
- 无标签行只写具体输入，可用性遵守优先级；
- `可用`、`需处理`行必须存在真实 `输入 -> 标签`；
- 数据类型合法并复用原表已有类型；
- `高` 关联均有可点名的直接标题监督，不以是否多页作为门槛；
- 表头、页眉、KIE HEADER、图表标题和普通 Markdown 未被误当作文档标题监督；
- `非数据集` 行的关联度为 `不相关`；
- 多页字段与关联度已独立复核，未仅凭其中一个推导另一个；
- 核心池同时给出 `C0` 与证据合格的 `C1`，持续门户或未冻结来源未混入覆盖率分母；
- 行数、家族去重数和文档/页数未互相替代；
- `非数据集` 不标物理多页；
- 关联原因不重复且包含数据集特定证据；
- XLSX/TSV 结构可读取，原始资产表未修改；
- 临时验证文件已清理，既有下载目录未受影响。

最终应由独立 agent 或独立审计脚本再执行一次只读核验，并报告明确的 PASS 或具体行号问题。
