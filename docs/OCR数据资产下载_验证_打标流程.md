# OCR 数据资产下载、验证与打标流程

这份文档是给人看的工作流程。它说明数据集如何探底、下载、验证和写入当前 TSV；不修改用户维护的 Excel。

## 一、开始前确认

1. 以用户最新的 `/Users/guofengjiao/Documents/文档解析数据集核心资产统计.xlsx` 为唯一当前名录。每次记录修改时间、SHA-256、sheet、表头和最大行号。
2. 读取 `注意事项/来源.png`、`类型.png`、`状态.png`、`可用性.png`。来源和类型是多选，状态和可用性是单选，不自行创造选项。
3. 现场检查 `/Volumes`，当前团队数据盘逻辑集合为 `modelscope1`、`shareData0`、`shareData1`、`shareData2`、`shareData3`。逻辑名称不等于实际挂载目录，K 列必须写实际存在的路径。
4. `shareData1/supportData` 是国内客服附件文档，不是运维资料。

## 二、先探底再下载

对天池、大型 ModelScope/Hugging Face 仓库、来源不清或大小不明的项目，先记录：

- 真实来源、官方链接、revision/版本；
- 文件数、manifest/tree、预计总大小、记录或页面数；
- 文件格式、许可、访问限制和是否需要登录；
- 是否存在输入与标签、是否可能直接用于 `pdf-markdown`；
- 下载结论：直接下载、分批下载、只保留探底结果或暂不下载。

小数据只有在来源稳定、大小明确、无需申请且可验证时才直接下载。大数据先看文件树、manifest、schema 或少量样本，不把页面显示的逻辑规模当成本地已下载大小。

来源优先使用官方项目页、数据卡和下载页；实际访问可以按 `ModelScope -> hf-mirror -> 官方 Hugging Face` 尝试。DocFusion 只能提供候选名称、别名或来源指针，不能作为 B/J 的真实来源。

## 三、下载目录规则

- 一行一个数据集文件夹，不混放，不把多个数据集合并成一个目录。
- 下载过程中的 `.partial`、`.incomplete`、`.crdownload`、锁文件和临时缓存不算数据集内容。
- 最终目录去掉行号前缀，例如 `288_数据集名` 改为 `数据集名`；目标目录已存在时停止，不覆盖、不合并、不静默改名。
- 数据集移动后先确认新目录完整，再更新 TSV 的 K；不要因为路径变化删除完整数据。
- 只有完全下载的数据进入“已下载资产” TSV；部分下载、下载中和只有样例的数据不计入。

## 四、完全下载验证门槛

一个数据集要进入 TSV，至少完成以下检查：

1. 预期文件或分片清单与实际文件一致，或固定 revision 的 tree/manifest 已逐项核对。
2. 文件非零，实际大小、expected bytes 或 hash 可以核对。
3. tar/zip/rar 完成归档格式或 CRC 检查；Parquet/JSON/JSONL/XML 等至少完成结构读取。
4. 没有未完成 payload；平台显示 completed 只能作为证据之一，不能代替本地清单和大小核对。
5. 需要配对的数据抽查输入、标签的 key、页码、尺寸、hash 或内容关系。

完整归档可以保留压缩包，不要求为了验证而全部解压。样例通过不等于全量通过；全量未验证时不能标记为完全下载。

## 五、TSV 固定字段

当前交付 TSV 固定 16 列，顺序如下：

```text
行号
A 数据集
B 来源
C 类型
D 状态
E 团队硬盘
F 是否多页
G 是否>500GB
H 数量
I 预览
J 原始链接
K 存储链接
L 备注
M 输入与标签
N 可用性
P review备注
```

不含 `O 是否review`。一个数据集一行，不拆成下载表和标签表。

- B 来源、C 类型：严格按选项图填写，多选用逗号分隔。
- D 状态、N 可用性：严格按选项图填写，单选。
- H 数量：按排除缓存和临时文件后的实际大小填写，展示单位只用 `MiB` 或 `GiB`。
- J 原始链接：真实官方落地页或下载页。
- K 存储链接：当前实际团队盘路径。
- P review备注：填写自动完整性、schema、pair、许可和未完成边界；自动检查不能冒充人工 Review。

## 六、输入、标签与可用性

### M 输入与标签

- 有真实 ground truth、参考 Markdown、结构化版面/表格/公式标签或问答答案时，写 `输入 -> 标签`。
- 没有标签时只写输入，不写箭头，不写“无标签”，也不把标题、页数、文件名和普通 metadata 当标签。
- 标签是 teacher 生成、弱标或程序生成时，在 L/P 说明来源和质量边界。
- `supportData` 没有人工作答或结构标签时，只写客服附件原始文件类型，不补造标签。

### N 可用性

固定选项为：

```text
非数据集 / 可用 / 仅评测 / 需处理 / 暂时不可用 / 缺label
```

按以下优先级判定：

1. `非数据集`：索引、目录、工具、搜索页或纯来源说明。
2. `暂时不可用`：下载失败、权限阻断、加密无法读取、损坏或无法确认 payload。
3. `仅评测`：明确是 benchmark/evaluation，标签仅用于测评。
4. `可用`：可读 PDF 输入、对应参考输出/ground truth、稳定配对，并能直接作为 `pdf-markdown` 输入/标签对。
5. `缺label`：有输入但没有目标任务对应的标签；只有 PDF 不能证明有标签。
6. `需处理`：已经确认存在标签或参考输出，但还需要解包、转换、结构化解析、join 或重新配对。

典型例子：

- 只有法律、登记、处罚或标准 PDF：M 只写输入，N 填 `缺label`。
- 有 PDF 和对应 Markdown 且配对稳定：M 写 `PDF -> Markdown`，N 才能填 `可用`。
- FinanceBench：M 写 `财务报告/问答 JSONL -> 问题、答案、证据文本、财务指标/来源页`；它不是 pdf-markdown 输入/参考输出对，N 填 `需处理`。
- 公式裁剪、场景 OCR、表格图像等已有标签但需要转换：N 填 `需处理`；明确评测集填 `仅评测`。

## 七、交付前检查

- 只生成新的 TSV，不回写用户 XLSX。
- 每行恰好 16 列，表头准确，行号和数据集名称按最新 XLSX 对账。
- H 使用 `MiB/GiB`；M 无标签不含箭头；N 与格式、标签和任务用途一致。
- 只有完整下载资产进入 TSV；J 是真实来源，K 是实际存储路径。
- 保留已交付 TSV，不意外覆盖或删除旧文件。
